# Ralph Loop Prompt — Game Completion

---

Execute every checkbox in docs/plans/2026-04-12-game-completion-plan.md in order, without skipping, without reordering, without shortcutting. The plan has 5 phases: Critical Fixes, Gates & Field Moves, Movement & Life, Content Polish, and Final Verification. Every checkbox must end up checked with evidence (commit hash, test output, map-analyzer output, screenshot). You are not allowed to mark a task complete until the evidence exists. This is a ralph loop — the same prompt feeds back to you repeatedly, and each iteration must make measurable forward progress. If an iteration makes zero forward progress, that is a failure state — diagnose why before continuing.

MAP ANALYZER DISCIPLINE. This is the single most important tool you have. After EVERY placement change (NPC position, Pokemon position, item ball position, hidden item position, gate tile), you MUST run node scripts/map-analyzer.mjs and verify ZERO unreachable entities in the output. Use node scripts/map-analyzer.mjs --test X,Y to validate a candidate position BEFORE writing it to code. Use game-map-data.json safePlacementTiles as the source of truth for valid positions — never guess a coordinate. If the map-analyzer reports ANY unreachable entity after your change, the change is wrong — pick a different position and try again. Committing code with unreachable entities is a loop violation.

MOVEMENT BEHAVIOR DISCIPLINE. No NPC or wild Pokemon may remain STATIONARY without explicit justification. The MovementBehavior enum has 9 types — use them. Wild Pokemon should default to LOOK_AROUND (rotate in place on timer). Route NPCs should have varied behaviors: WANDER_LEFT_RIGHT for wanderers, LOOK_AROUND for watchers, WANDER_AREA for city NPCs, PACE_HORIZONTAL for sentries. After assigning movement, verify via runtime (Playwright browser_evaluate) that the NPC actually moves or rotates. Frozen NPCs that are supposed to move is a bug.

TESTING DISCIPLINE. After EVERY code edit, run npx tsc --noEmit + npx vitest run + npm run build. After placement changes, run the map-analyzer. After pushing, verify on production via Playwright browser_evaluate fetch() that the deployment works. Take screenshots on 3 viewports (desktop 1440x900, mobile landscape 852x393, mobile portrait 393x852) after visual changes. Check browser_console_messages for zero errors. A commit with a green build but unreachable entities in the map-analyzer is NOT verified.

PHASE GATES. You may not start Phase N+1 until Phase N's gate criteria are met. Phase 1 gate: map-analyzer reports ZERO unreachable entities + all unit tests pass. Phase 2 gate: GATES array has 2 entries + gate unit tests pass. Phase 3 gate: 50%+ entities have non-STATIONARY behavior. Phase 4 gate: all bug fixes committed + phone number shows real digits. Phase 5 gate: full production verification on 3 viewports.

COMMIT DISCIPLINE. Each fix gets its own commit. Do not batch unrelated fixes. Commit message must reference the plan task (e.g., "fix(1.1): set gymComplete when all 6 trainers cleared"). Push after each phase (not after each commit — push at phase boundaries to avoid 50 Vercel deploys).

ANTI-COMPROMISE CLAUSES. Forbidden: (a) guessing a coordinate without checking safePlacementTiles or running --test; (b) skipping the map-analyzer after a placement change; (c) leaving any wild Pokemon as STATIONARY without a documented reason; (d) emitting the completion promise while any plan checkbox is unchecked; (e) trusting that an NPC "should be reachable" without evidence from the analyzer; (f) committing code with more than zero unreachable entities in the map-analyzer output.
